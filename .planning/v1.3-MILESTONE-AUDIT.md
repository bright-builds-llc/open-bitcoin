### D-02: Support bundle live-smoke summary is shallow for schema v2

**Affected requirement:** OBS-03

The Phase 50 support evidence recorded the selected live-smoke report path, but
the allowlisted summary field reported `summary_fields_unavailable`. Current
live-smoke schema keeps useful status, typed cause, deltas, and next action under
nested `result`, while support ingestion summarizes only a shallow allowlist.

Follow-up: teach support evidence ingestion to summarize schema v2 nested
`result` fields without embedding raw logs or sensitive inputs.

### D-03: Historical Phase 50 selected report remains historical

**Affected requirements:** PROOF-03, PROOF-04, PROOF-05, OBS-02, SEC-03

The committed Phase 50 UAT intentionally preserves the selected generated report
as historical evidence. That report used `getblockchaininfo` snapshots and shows
the stale `rpc_getblockchaininfo` phase. Phase 51 amended the evidence trail and
fixed future live-smoke polling; auditors should read Phase 50 together with
the Phase 51 summary and verification.

### D-04: `open-bitcoind` preflight message is stale

**Affected requirement:** OBS-02

stderr still says peer transport and unattended full IBD are not started by this
phase. This is an operator-message debt item, not a runtime integration blocker.

Follow-up: refresh the message to describe the current opt-in worker and the
remaining non-claims without contradicting runtime behavior.
