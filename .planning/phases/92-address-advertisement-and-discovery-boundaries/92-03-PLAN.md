## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inbound `addr` payload -> learned-address book | Untrusted peer address announcements enter typed acceptance/rejection policy. |
| learned/local address store -> `getaddr` response | Stored address evidence may be sent back to an eligible inbound peer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-92-03-01 | Tampering | `LearnedAddressBook` | mitigate | Reject invalid ports, stale/future timestamps, duplicates, unroutable entries, unsupported networks, and over-cap batches with stable reasons. |
| T-92-03-02 | Denial of Service | learned-address batch intake | mitigate | Enforce `PHASE92_LEARNED_ADDR_BATCH_LIMIT = 64` and avoid unbounded persistence or randomized buckets. |
| T-92-03-03 | Information Disclosure | `select_getaddr_response` | mitigate | Filter to publicly routable, non-stale, policy-approved entries and cap responses at `PHASE92_GETADDR_RESPONSE_LIMIT = 8`. |
| T-92-03-04 | Denial of Service / Information Disclosure | repeated getaddr | mitigate | Track served-once request state and return `already_served` suppression without rebuilding unbounded work. |
| T-92-03-05 | Repudiation | relay/discovery boundary | mitigate | No strings or APIs for relay queues, DNS seeds, randomized buckets, or addrman/peers.dat persistence are introduced. |
</threat_model>
