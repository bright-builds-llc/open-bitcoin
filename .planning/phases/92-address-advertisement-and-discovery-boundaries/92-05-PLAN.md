## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pure peer evidence -> node status | Address decisions cross from pure peer state into serialized status evidence. |
| status -> operator/RPC consumers | Shared status becomes visible to local CLI/RPC/support surfaces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-92-05-01 | Information Disclosure | `InboundPeerServingStatus` address fields | mitigate | Serialize bounded source/routability/freshness/services/port evidence, not raw address bytes, peer IDs, raw class names, or raw config. |
| T-92-05-02 | Repudiation | shared evidence labels | mitigate | Use stable labels for local advertisement, getaddr, learned accepted/rejected, and full relay deferred boundaries. |
| T-92-05-03 | Denial of Service | status projection | mitigate | Project bounded vectors and counts from PeerManager evidence instead of raw unbounded address tables. |
| T-92-05-04 | Tampering | legacy status compatibility | mitigate | Serde defaults preserve unavailable reasons for older snapshots so missing fields cannot be mistaken for positive support. |
</threat_model>
