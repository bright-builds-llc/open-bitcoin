<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Negotiated peer state -> announcement decision | Peer-provided `sendcmpct` preference affects whether local policy allows direct compact announcements. |
| Local block/resource facts -> announcement action | Local availability and resource-pressure facts decide whether to announce, fall back, or suppress. |
| Decision reasons -> later evidence surfaces | Fixed labels created here will be reused by later operator evidence work. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-02-01 | Elevation of Privilege | `decide_compact_announcement` | mitigate | Gate on `activation.compact_relay.enabled` before peer capability or permissions, and test disabled activation explicitly. |
| T-113-02-02 | Tampering | Header continuity facts | mitigate | Require previous-header-known and current-header-not-known booleans before `AnnounceCompactBlock`; failed continuity returns headers fallback, not compact. |
| T-113-02-03 | Denial of Service | Resource gate consumption | mitigate | Suppress compact announcement when `BlockServingResourceGateDecision.may_serve_block` is false, using fixed `compact_resource_limited` reason. |
| T-113-02-04 | Information Disclosure | `CompactAnnouncementReason::as_str` | mitigate | Reasons are fixed low-cardinality strings and contain no peer ID, block hash, transaction ID, permission text, or dynamic resource values. |
| T-113-02-05 | Spoofing | `PeerManager::decide_compact_announcement_for_peer` | mitigate | Unknown peer IDs return `NetworkError::UnknownPeer`; the method reads compact state only from the stored peer record. |
</threat_model>
