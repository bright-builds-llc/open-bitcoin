<threat_model>
Threats:
- Resource collection can accidentally recurse into raw stores or support outputs and make status slow or huge.
- Disk guidance can be nondeterministic in tests if it depends on the host filesystem.
- Introducing a filesystem dependency can break Bazel if BUILD files are not kept in sync.

Mitigations:
- Probe only allowlisted roots and return bounded byte/file counts.
- Keep classifier tests pure and use injected probe fixtures for edge cases.
- If `fs4` is used for free/available/total space, update Cargo and Bazel deps together and keep all policy decisions in first-party code.
- Keep probe orchestration in `open-bitcoin-cli/src/operator/status/resource_bounds.rs`; do not move filesystem effects into pure node status contracts.
</threat_model>
