<threat_model>
Threats:
- A soak can start when disk/support/log pressure is already stop-required, producing opaque failure evidence.
- A soak can start when enforcement is requested but required resource measurements are missing or the datadir cannot be assessed.
- Runtime pressure can be observed but not recorded as a terminal resource stop.
- Resume logic can incorrectly reject resource-stop runs and lose durable progress.

Mitigations:
- Run a preflight resource snapshot before `Started` is appended; refuse stop-required pressure, zero/invalid disk budgets, missing or unassessable datadirs, and unavailable required resource evidence when enforcement is requested.
- Evaluate `ResourceBoundSnapshot.overall_level` during checkpoints and append `Stop` plus `Verdict` as `resource_stop`.
- Persist source evidence for the resource stop, including resource-bound trigger labels, recovery/no-progress details when available, and the status snapshot source path.
- Keep Phase 75 `validate_resume_plan` behavior where `resource_stop` resumes as the same run.
</threat_model>
