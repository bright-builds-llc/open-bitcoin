<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Fjall mempool snapshot -> managed recovery replay | Durable bytes may be corrupt, stale, schema-incompatible, or adversarially malformed before becoming in-memory mempool state. |
| Managed recovery replay -> relay-serving/fanout state | Recovered transaction material becomes serveable only if current policy and chainstate checks accept it. |
| Recovery replay -> peer socket output | Startup replay must not cross into socket I/O, `inv`, or public fanout emission. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-108-01 | I | `ManagedMempoolRecoverySummary` and storage-error evidence | mitigate | Store only fixed counters, `StorageRecoveryAction`, and `SyncRecoveryCategory`; never persist raw transaction hex, txids, wtxids, storage detail strings, peer ids, endpoints, permission strings, or credentials. |
| T-108-02 | T | `recover_mempool_snapshot` | mitigate | Re-accept every recovered record through `MempoolSnapshot::replay_into_mempool` against current chainstate, policy, and consensus parameters before calling `store_transaction`. |
| T-108-03 | R | startup recovery path | mitigate | Add deterministic tests proving recovered accepted records are serveable locally but recovery itself returns no `WireNetworkMessage` and does not call fanout drain/translation. |
| T-108-04 | D | corrupt or schema-incompatible snapshots | mitigate | Route `StorageError` through typed safe diagnosis and avoid `clear_mempool_snapshot`, compaction, reindex, destructive repair, or source datadir mutation in recovery replay. |
| T-108-05 | S | false public-propagation claims | mitigate | Use no-socket recovery method names and tests; later checker plan must reject public propagation, public relay default, production readiness, compact block, package relay, and bloom/filter claims. |
</threat_model>
