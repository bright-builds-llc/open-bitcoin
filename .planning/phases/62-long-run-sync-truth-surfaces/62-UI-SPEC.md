# Phase 62 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 62 is a terminal/operator truth-surface phase, not a hosted dashboard,
GUI, marketing page, or decorative frontend. The contract applies to
`open-bitcoin status`, `open-bitcoin dashboard`, `open-bitcoin sync status`,
RPC sync status/warnings, metrics/log summaries, and opt-in live-smoke
JSON/Markdown snapshots. Source: `62-CONTEXT.md`, `62-RESEARCH.md`,
`REQUIREMENTS.md` OBS-01/OBS-02.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Conceptual one-character gap between inline label/value tokens |
| sm | 8px | Compact spacing inside terminal summaries and Markdown table cells |
| md | 16px | One blank line between major Markdown report sections |
| lg | 24px | Separation between operator report blocks when rendered outside a TTY |
| xl | 32px | Reserved for docs pages around command blocks |
| 2xl | 48px | Not used by Phase 62 runtime surfaces |
| 3xl | 64px | Not used by Phase 62 runtime surfaces |

Exceptions: terminal output may use a single ASCII space after `:` and Markdown
pipe tables may use the minimum spaces required for readable table syntax. Do
not add blank-line padding inside compact `status`, `sync status`, dashboard
rows, JSON, structured logs, or snapshot tables.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` | Rendered report background or default terminal background equivalent |
| Secondary (30%) | `#E5E7EB` | Markdown table borders, dashboard section dividers, muted report surfaces |
| Accent (10%) | `#2563EB` | Active dashboard focus row, selected non-destructive action, progress-positive marker only |
| Destructive | `#B91C1C` | Existing destructive dashboard actions only; Phase 62 must not add new destructive actions |

Accent reserved for: current dashboard focus, selected non-destructive action,
and progress-positive markers. Do not use accent for every interactive label,
JSON fields, structured log fields, unavailable states, warnings, or decorative
backgrounds.

Unavailable values use neutral text with the literal prefix `Unavailable:`.
Errors and warnings use existing health/error styling only when a surface
already supports it; otherwise render plain text.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Review sync status |
| Empty state heading | No sync truth available |
| Empty state body | Start an explicit opt-in mainnet sync or inspect a datadir with durable sync metadata, then rerun status. |
| Error state | Sync truth unavailable: {reason}. Inspect the selected datadir, config, RPC credentials, and durable sync metadata before retrying. |
| Destructive confirmation | none; Phase 62 introduces no destructive actions or service-supervision controls |

Copy rules:

- Use `Unavailable: {reason}` everywhere a typed field is absent. Never render
  missing numeric state as `0` unless the underlying typed value is truly zero.
- Keep machine labels snake_case in JSON, logs, metrics, and compact human
  status: `header_progress`, `waiting_for_peers`,
  `public_network_unreachable`.
- Human guidance may be sentence case, but it must not rename stable
  `SyncRecoveryCategory` or progress-signal labels.
- Do not imply production-node support. Use "opt-in mainnet review",
  "bounded sync", and "operator review" language.

## Terminal Output Contract

### Field Order

All human operator truth surfaces that show sync status must keep this order
when the field is present in the surface:

| Order | Label | Backing field |
|-------|-------|---------------|
| 1 | Sync lifecycle / State | `sync.lifecycle` |
| 2 | Sync phase / Phase | `sync.phase` |
| 3 | Configured targets | target outbound peers and optional target header height |
| 4 | Attempt counters | peer attempts and bounded cycle counters |
| 5 | Progress signal / Signal | `sync.progress_signal` |
| 6 | Last progress | `sync.last_successful_progress_unix_seconds` |
| 7 | Latest stop reason | typed stop reason or explicit unavailable reason |
| 8 | Latest error / Last error | `sync.last_error` |
| 9 | Recovery category | `sync.recovery_category` |
| 10 | Recovery action / Recovery | `sync.recovery_action` |
| 11 | Resource pressure / Pressure | `sync.resource_pressure` |
| 12 | Peer health / Peers | peer counts and recent peer telemetry |
| 13 | Header height | `sync.sync_progress.header_height` |
| 14 | Downloaded block | `downloaded_block_height` and `maybe_downloaded_block_hash` |
| 15 | Connected block | `connected_block_height` and `maybe_connected_block_hash` |
| 16 | Bounded counters | `messages_processed`, `headers_received`, `blocks_received` |

Surfaces may group fields into existing sections such as "Sync and Peers", but
must not invert downloaded and connected block evidence or hide unavailable
fields.

### Compact Rows

- `open-bitcoin status` remains one label/value row per truth fact.
- `open-bitcoin sync status` remains compact and line-oriented; it should grow
  by adding required Phase 62 rows, not by embedding long paragraphs.
- Dashboard rows use the existing `DashboardSection`/`DashboardRow` model.
- Live-smoke Markdown snapshot tables stay bounded and must not embed raw
  daemon tails, full endpoint tables, or unbounded snapshot history.
- JSON and structured logs preserve typed fields; human labels are not the
  source of truth.

## JSON And Human Parity

The same Phase 62 truth fields must be available across status, dashboard, RPC,
metrics/logs, and live-smoke where the source has that fact. Naming rules:

- Rust serde and RPC fields use snake_case.
- TypeScript live-smoke report fields may use camelCase only through one
  mapping layer.
- Markdown headings and table labels use concise title case or sentence case.
- Human output labels may shorten `last_successful_progress_unix_seconds` to
  `Last progress`, but tests must prove it maps to the typed field.
- `FieldAvailability` reasons and report-level `null` summaries are diagnostic
  evidence and must be preserved.

Required status states:

| State family | Stable labels |
|--------------|---------------|
| Lifecycle | `active`, `paused`, `recovering`, `failed`, `stopped` |
| Progress signal | `header_progress`, `block_progress`, `waiting_for_peers`, `peer_failures`, `awaiting_blocks`, `steady` |
| Recovery category | `clean_shutdown`, `unclean_shutdown`, `incompatible_schema`, `store_corruption`, `storage_lock_contention`, `storage_backend_failure`, `resource_exhaustion`, `invalid_peer_data`, `public_network_unreachable`, `operator_cancellation` |
| Stop/waiting evidence | `target_header_reached`, `no_progress`, `max_rounds_reached`, `operator_paused`, `shutdown_requested`, `retry_backoff`, storage failure, resource limit, peer failure |

## Live-Smoke Snapshot Contract

Live-smoke JSON and Markdown reports must remain opt-in UAT evidence and stay
outside `bash scripts/verify.sh` public-network execution. Deterministic fixture
checks may validate generated reports.

Snapshot tables must include, at minimum:

- captured timestamp
- lifecycle
- phase
- progress signal
- header height
- downloaded block height and hash
- connected block height and hash
- outbound peers versus configured target
- recovery category
- resource pressure summary
- latest stop reason or `Unavailable: {reason}`
- latest error or `Unavailable: {reason}`

When no snapshots exist, render one explicit unavailable row instead of an empty
table or a success-looking zero row.

---

## Out Of Scope

Do not add or specify:

- hosted dashboards, browser UI, GUI parity, landing pages, or decorative
  layouts
- new service-supervision controls or lifecycle commands
- broad production-node claims
- public-network long-run checks in default verification
- third-party UI registries or new frontend dependencies
- unbounded metrics samples, log lines, endpoint tables, daemon output tails, or
  raw live-smoke report material
