## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sync evidence -> no-progress diagnosis | Mixed peer, storage, resource, and chain evidence determines operator guidance. |
| shared status -> CLI/RPC/dashboard consumers | Renderer code must not invent different diagnosis strings. |
| public peer behavior -> operator next action | Malicious peer stalls/failures can influence guidance if precedence is wrong. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-05-01 | Spoofing / Repudiation | no-progress status | mitigate | Derive diagnosis from typed `StayCurrentStatus`, `SyncProgressSignal`, `SyncRecoveryCategory`, `PeerSyncOutcome`, resource pressure, and reconcile progress. |
| T-70-05-02 | Denial of Service | peer-guidance precedence | mitigate | Storage and resource blockers outrank peer retry advice; backoff/stall/failure diagnoses stay distinct. |
| T-70-05-03 | Tampering | renderer-local strings | mitigate | CLI rendering reads `SyncStatus.no_progress_diagnosis` and `SyncStatus.no_progress_next_action` instead of reclassifying text. |
| T-70-05-04 | Information Disclosure | next-action text | mitigate | Guidance stays bounded and does not include raw peer logs, raw undo data, credentials, or wallet data. |
</threat_model>
