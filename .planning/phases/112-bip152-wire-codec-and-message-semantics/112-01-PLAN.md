<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| peer bytes -> `decode_send_compact_payload` | Untrusted P2P payload bytes become a typed `SendCompactMessage`. |
| codec payload -> `WireNetworkMessage` | Decoded payload data enters the network message enum before later peer policy exists. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-112-01-01 | Tampering | `decode_send_compact_payload` | mitigate | Require exactly one boolean byte plus one little-endian `u64`; short payloads return `CodecError::UnexpectedEof` and trailing bytes return `CodecError::TrailingData`. |
| T-112-01-02 | Denial of Service | `sendcmpct` decoder | mitigate | Decode a fixed 9-byte payload only; do not allocate based on peer-controlled lengths. |
| T-112-01-03 | Spoofing | unsupported `sendcmpct` versions | accept | Unsupported versions decode as data by design per D-02; Phase 113 owns peer capability and announcement suppression policy. |
| T-112-01-04 | Elevation of Privilege | `WireNetworkMessage::SendCompact` | mitigate | Keep `sendcmpct` out of `GetData`, `Block`, transaction relay, node-shell, mempool, and serving paths; this plan only maps command bytes to typed data. |
</threat_model>
