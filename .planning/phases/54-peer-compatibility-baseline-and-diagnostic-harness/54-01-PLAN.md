# Plan 54-01: Hermetic Peer Compatibility Transcript Harness

<objective>
Add a deterministic pure-core peer compatibility harness that compares Open
Bitcoin's early outbound P2P transcript shape against the pinned Knots baseline
surface and reports typed diagnoses for handshake or early-protocol failures.
</objective>

<threat_model>

## Assets

- Public-mainnet peer compatibility evidence.
- Operator-facing diagnosis text and future live-smoke integration data.
- Pure network state invariants in `open-bitcoin-network`.

## Threats

- **High:** A failed peer transcript is reported as useful progress, causing
  later phases to credit incompatible peers.
- **Medium:** Malformed or wrong-network wire bytes collapse into vague text,
  preventing operators from distinguishing payload, network, and local config
  issues.
- **Medium:** The harness drifts into live network behavior and makes default
  verification depend on public peers.

## Mitigations

- Typed diagnosis enum variants are asserted in deterministic tests.
- Report steps carry explicit command names and useful-progress flags.
- Implementation stays in the pure network crate and default verification uses
  `bash scripts/verify.sh`, with no public-network command added to the default
  gate.

</threat_model>

<action>

Create `packages/open-bitcoin-network/src/compatibility.rs` with a parity
breadcrumb block anchored to:

- `packages/bitcoin-knots/src/net_processing.cpp`
- `packages/bitcoin-knots/test/functional/p2p_handshake.py`
- `packages/bitcoin-knots/test/functional/p2p_initial_headers_sync.py`

Define and expose:

- `CompatibilityDiagnosis` enum with variants:
  `Compatible`, `VersionRejected`, `NetworkMismatch`, `ServiceBitMismatch`,
  `UnsupportedMessageOrder`, `Timeout`, `PeerDisconnect`,
  `MalformedPayload`, and `LocalConfigurationFailure`.
- `TranscriptEvent` enum for deterministic inputs:
  `OutboundConnect`, `ReceiveMessage(WireNetworkMessage)`,
  `ReceiveWire(Vec<u8>)`, `Timeout`, and `PeerDisconnect`.
- `TranscriptStep` struct with fields `event: String`,
  `observed_command: Option<String>`, `sent_commands: Vec<String>`,
  `diagnosis: CompatibilityDiagnosis`, and `useful_progress: bool`.
- `CompatibilityReport` struct with fields `transcript_name: String`,
  `steps: Vec<TranscriptStep>`, `diagnosis: CompatibilityDiagnosis`,
  `useful_progress: bool`, and `next_action: String`.
- `evaluate_transcript(name: impl Into<String>, events: impl IntoIterator<Item = TranscriptEvent>) -> CompatibilityReport`.

The evaluator must use `PeerManager`, `WireNetworkMessage::command_name()`, and
`ParsedNetworkMessage::decode_wire()` rather than duplicating peer logic. It
must map:

- duplicate remote `version` disconnect to `VersionRejected`
- decoded wire messages whose header magic is not `NetworkMagic::MAINNET` to
  `NetworkMismatch`
- decode errors to `MalformedPayload`
- remote `version` missing `ServiceFlags::NETWORK` or `ServiceFlags::WITNESS`
  to `ServiceBitMismatch`
- `WtxidRelay` received after remote `Verack` to `UnsupportedMessageOrder`
- scripted timeout to `Timeout`
- scripted disconnect to `PeerDisconnect`
- inability to initialize the local outbound peer to `LocalConfigurationFailure`

Export the new types from `packages/open-bitcoin-network/src/lib.rs`.

</action>

Tests must prove:

- a Knots-like outbound transcript emits `version`, then responds to remote

  `getheaders` after remote `verack`

  `CompatibilityDiagnosis::NetworkMismatch`

  `CompatibilityDiagnosis::ServiceBitMismatch`
- `wtxidrelay` after remote `verack` maps to
  `CompatibilityDiagnosis::UnsupportedMessageOrder`
- scripted timeout maps to `CompatibilityDiagnosis::Timeout`
- scripted disconnect maps to `CompatibilityDiagnosis::PeerDisconnect`
- every non-compatible report has `useful_progress == false`
