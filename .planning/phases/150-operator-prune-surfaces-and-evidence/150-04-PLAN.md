## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Node chain walk → getblockchaininfo | Clients treat pruneheight as the Knots info integer. |
| JSONC and RPC → CLI snapshot | A stopped collector must not invent a live height or a zero count. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-01 | Spoofing | getblockchaininfo.pruned | mitigate | The field is `project_prune_status(...).pruned`. Tests keep the earned `pruned_count` on the block-serving path. Durability JSON is not given a pruned key. |
| T-150-02 | Tampering | manual prune | accept | The snapshot only stores `ManualPruneSurface`. Plan 05 is the only writer of a height or refusal, and it refuses before flush. |
| T-150-03 | Tampering | lock resume | accept | Plan 03 already loads locks. This plan reads `load_prune_locks` for display. |
| T-150-04 | Information disclosure | snapshot locks versus support | mitigate | Lock names may sit on `PruneOperatorStatus.locks` for the dashboard. They are not copied into `chainstate_durability` or `PruneSupportCounts`. Plan 08 must not print `locks` in the support section. |
| T-150-05 | Tampering | stopped mode | mitigate | Stopped mode comes from `parse_prune_arg` on the already loaded JSONC integer. Invalid config never reaches a running collector. |
| T-150-06 | Tampering | lock name as a path | accept | This plan only copies loaded rows. It does not join names onto the datadir. |
</threat_model>
