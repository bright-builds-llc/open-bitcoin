<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public peer network -> sync runtime | Untrusted peers can fail, stall, disconnect, send invalid data, or trigger resource limits. |
| RPC/CLI control -> daemon loop | Operator pause/resume/status requests modify durable control state used by the background thread. |
| daemon process lifecycle -> durable store | Startup, failure, pause, and shutdown must leave auditable state for later operator review. |
| docs/UAT -> release interpretation | Operator review language can be mistaken for production-node readiness if boundaries drift. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-01-01 | Denial of Service | daemon sync loop | mitigate | Policy helper sleeps at least `max(retry_backoff_ms, 1000ms)` between cycles and tests prove failed/waiting peers do not hot-loop. |
| T-60-01-02 | Repudiation | durable loop state | mitigate | Persist typed pause, shutdown, failure, target, no-progress, and max-round stop reasons through durable status and structured logs. |
| T-60-01-03 | Tampering | peer contribution counters | mitigate | Retry/backoff tests assert failed and waiting peers have zero useful header/block contribution. |
| T-60-01-04 | Elevation of privilege | operator control state | mitigate | Reuse existing RPC/store-backed pause/resume; do not add a second unaudited control file. |
| T-60-01-05 | Information disclosure | docs/support boundary | accept | Phase 60 docs do not add support bundle fields; Phase 65 owns redacted support evidence. |
| T-60-01-06 | Spoofing | release claims | mitigate | Docs keep unattended operation framed as extended operator review, not production-node readiness. |
</threat_model>
