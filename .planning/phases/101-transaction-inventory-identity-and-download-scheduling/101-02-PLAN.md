<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| peer message -> PeerManager | Untrusted peer `inv`, `getdata`, `notfound`, and `tx` messages enter peer state. |
| PeerManager -> ManagedPeerNetwork | Pure typed actions cross into the managed shell that can emit wire messages or submit received transactions. |
| disconnect/timeout -> fallback scheduling | Peer lifecycle changes can trigger request fallback to another peer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-101-02-01 | Spoofing | `handle_inventory` negotiation handling | mitigate | Build `TxAnnouncementInput.peer_mode` from `PeerState.remote_wtxidrelay`; mismatched `MSG_TX` or `MSG_WTX` emits `SuppressIdentityMismatch` and creates no request state. |
| T-101-02-02 | Tampering | `handle_transaction` received data cleanup | mitigate | Derive txid and wtxid once with consensus helpers, call `record_received_transaction`, and avoid appending `ReceivedTransaction` when scheduler emits `SuppressIdentityMismatch`. |
| T-101-02-03 | Denial of Service | `handle_inventory` and request pressure accounting | mitigate | Replace bare tx request sets with scheduler counts and still feed Phase 94 request pressure caps before returning request actions. |
| T-101-02-04 | Denial of Service | `remove_peer_with_transaction_cleanup` and `expire_transaction_requests` | mitigate | Remove stale peer/in-flight records, emit fixed cleanup/expiry labels, and choose fallback candidates without re-requesting from failed peers. |
| T-101-02-05 | Information Disclosure | `process_transaction_relay_action` | mitigate | Translate only request/fallback actions into `GetData`; do not log or expose raw txids, wtxids, transaction hex, peer endpoints, permission strings, credentials, or dynamic labels. |
| T-101-02-06 | Elevation of Privilege | Managed transaction relay bridge | mitigate | Do not interpret relay-like permissions, do not bypass Phase 100 activation policy, and do not add mempool admission outcomes, serving/fanout, rebroadcast, RPC, metrics, logs, or support surfaces in this phase. |
</threat_model>
