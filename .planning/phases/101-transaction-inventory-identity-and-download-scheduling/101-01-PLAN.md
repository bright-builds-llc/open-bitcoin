<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| peer inventory -> scheduler | Untrusted `inv`, `getdata`, and `notfound` hashes and type tags enter typed transaction scheduling. |
| peer transaction bytes -> cleanup input | Untrusted raw transaction material is reduced to consensus-derived txid and wtxid before cleanup. |
| scheduler evidence -> later status/log surfaces | Typed action labels may later be projected to operator evidence and must stay low-cardinality. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-101-01-01 | Spoofing/Tampering | `TxRelayId::from_inventory_vector_for_peer` | mitigate | Convert `InventoryVector` to `TxRelayId` only when `InventoryType::Transaction` matches `TxRelayPeerMode::TxidOnly` or `InventoryType::WitnessTransaction` matches `TxRelayPeerMode::WtxidRelay`; emit `suppress_identity_mismatch` and store no candidate otherwise. |
| T-101-01-02 | Denial of Service | `TxDownloadScheduler::record_announcement` | mitigate | Enforce `PHASE101_MAX_TX_ANNOUNCEMENTS_PER_PEER = 5_000` and `PHASE101_MAX_TX_REQUESTS_IN_FLIGHT_PER_PEER = 100`, emit `suppress_request_cap`, and keep tests for cap suppression. |
| T-101-01-03 | Denial of Service/Tampering | fallback selection after timeout, `notfound`, and disconnect | mitigate | Retain duplicate announcers as fallback candidates, remove stale in-flight records before fallback, and avoid re-requesting from the same failed peer for the same identity. |
| T-101-01-04 | Information Disclosure | `TxDownloadAction::as_str` and `TxDownloadSuppressionReason::as_str` | mitigate | Return only fixed labels such as `request_getdata`, `suppress_recent_reject`, and `request_expired`; do not include txids, wtxids, peer endpoints, permission strings, transaction hex, credentials, or dynamic labels. |
| T-101-01-05 | Tampering | `record_received_transaction` | mitigate | Require caller-supplied consensus txid and wtxid, mark both identities already-have, and clear only matching in-flight state for the peer. |
</threat_model>
