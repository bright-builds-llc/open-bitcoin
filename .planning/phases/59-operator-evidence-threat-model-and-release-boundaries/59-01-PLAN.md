## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sync runtime -> operator surfaces | Durable sync summaries become user-facing status, dashboard, metrics, logs, RPC, and live-smoke evidence. |
| public peer evidence -> reviewer interpretation | Peer activity, failures, and useful progress can be mistaken for stronger sync success if fields drift. |
| deterministic fixtures -> default verification | Fixture checks must remain local and must not invoke public-network live smoke. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-59-01-02 | Spoofing, Repudiation | RPC `getblockchaininfo` | mitigate | Assert RPC `blocks` remains the connected-height compatibility alias and does not report downloaded-only evidence as connected progress. |
| T-59-01-03 | Repudiation | CLI status/dashboard renderers | mitigate | Assert renderers display exact shared snapshot values and latest error text from the fixture. |
| T-59-01-04 | Denial of Service | default verification | mitigate | Acceptance requires `scripts/verify.sh` stays free of `run-live-mainnet-smoke` and `--restart-after-progress`. |
