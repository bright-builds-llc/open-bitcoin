<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local live-smoke report -> support bundle | A potentially large local report is reduced to an allowlisted evidence summary. |
| local config/status/store data -> reviewer artifact | Local paths, metadata, and unavailable reasons are shared while secrets and raw artifacts stay local. |
| missing optional evidence -> support output | Missing live-smoke, metrics, logs, RPC, or store evidence must remain visible as diagnostic context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-02-01 | Information Disclosure | `support/live_smoke.rs` | mitigate | Use purpose-built allowlisted field extraction and forbidden-marker tests for daemon tails, snapshots, endpoint tables, manual peers, cookies, wallet material, and secrets. |
| T-59-02-02 | Tampering, Repudiation | support summary fields | mitigate | Preserve exact field names for status, first header, first block, restart/resume, recovery diagnosis, peer outcome counts, and final status so reviewers can map support output back to live-smoke reports. |
| T-59-02-03 | Spoofing | support bundle semantics | mitigate | Tests and later docs state support bundles are local review evidence only, not public-mainnet proof or release validation. |
| T-59-02-04 | Denial of Service | support artifact size | mitigate | Summarize compact objects only; do not embed raw arrays such as snapshots or endpoint outcome tables. |
| T-59-02-05 | Elevation of Privilege | credential reporting | mitigate | Preserve metadata-only credential reporting and redaction for `rpcpassword`, `rpcauth`, cookie values, and wallet material. |
</threat_model>
