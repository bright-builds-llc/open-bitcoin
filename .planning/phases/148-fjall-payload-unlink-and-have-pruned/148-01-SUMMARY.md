**One Sync batch tombstones a height's block payload and undo, and records have-pruned only inside that batch when a live mate existed**

## Accomplishments

- `commit_paired_delete` removes `block:<64-hex>` and `undo:<64-hex>` in one `PersistMode::Sync` (`SyncAll`) batch when either mate is present, then requires both `contains_key` probes to be false.
- `have_pruned` is inserted only in that second batch. Both mates already absent returns `AlreadyAbsent` with no intent write and no marker. A separate `sync_prune_intent` commit does not set the marker.
- `has_undo` is a chainstate `contains_key` probe. The batch does not touch the coins best-block key. New files are covered by `node-fjall-prune-unlink`.
