# Phase 148 Plan 03: Finish or Refuse an Interrupted Prune

<objective>
On startup, finish the one height named by `prune_intent` or refuse closed, without inventing payload bytes or asking for reindex (UNLK-03; D-08..D-10).

Purpose: A crash between the intent commit and the delete commit must not look like a missing block that should be reindexed, and must not serve a half-deleted height.
Output: `resume_prune_intent` called from `initialize`, plus injected seam tests. No automatic reindex, no coins repair, no new public initialize arguments.
</objective>

Do not change the public signature of `initialize`. Inside it, after `apply_recovery_decision` succeeds and before `lifecycle.readiness = ManagerReadiness::ReadyToFlush`, call:

```rust
resume_prune_intent(store, &[])?;
```

Locks are not durable until Phase 150. The empty slice is intentional (research assumption A1). The in-process flush path from Plan 02 still re-checks caller-supplied locks. Do not add a lock parameter to `initialize`.

```rust
pub(crate) fn resume_prune_intent(
    store: &FjallNodeStore,
    locks: &[PruneLockInfo],
) -> Result<(), StorageError>;
```

Place the function in `fjall_store/prune.rs`. `flush_lifecycle.rs` is already near enough of the 628-line gate that the resume body stays in `prune.rs`. `initialize` only calls it.

When `maybe_prune_intent` is `Ok(None)`, return `Ok(())`.

When an intent is present, load the active chain with `FjallNodeStore::load_chain_meta_for_open` (the `Vec<ChainPosition>` is the first tuple field). Tip is `active_chain.last()`. Load coins best-block with `FjallCoinsView::from_store(store).best_block()`.

Refuse with `StorageError::Corruption { namespace: StorageNamespace::BlockIndex, action: StorageRecoveryAction::Repair, detail }` when any of these hold (D-08, D-09, D-10). Detail contains `fail_closed` and says the node stopped closed and did not reindex. Do not use `InterruptedWrite`. Do not use `StorageRecoveryAction::Reindex`. Do not call `mark_interrupted_write`.

- Intent hash is not the `block_hash` of the active-chain position whose `height` equals `intent.height`.
- Active chain is empty, or `height_inside_keep_window(tip.height, intent.height)`.
- `height_forbidden_by_any_lock(intent.height, locks)`.
- `best_block()` is `Ok(Some(hash))` and that hash is not `active_chain.last().block_hash`. This is the injected seam where an undo delete was paired with a coins tip move (D-12). A best-block that matches the recorded tip is normal and does not refuse.

Refuse leaves every remaining mate key in place and does not call `save_block` or `save_undo`. `initialize` returns that error, so `readiness` stays `NotReady` (D-10).

Otherwise finish the same height:
- Both mates present, or exactly one present: `commit_paired_delete(intent.height, intent.block_hash)`. Have-pruned is set only by that function's live-mate batch. Do not write an empty body (D-03, D-08).
- Both mates already absent: Sync-remove `PRUNE_INTENT_KEY` only. Do not insert `have_pruned` in that cleanup (D-07).
- `have_pruned` already set and one mate still present, hash still active, not locked, not in the keep window: finish through `commit_paired_delete`. Success means both probes are false afterward. Do not report success while a key remains.

`commit_paired_delete` already writes a fresh intent before its tombstone batch. Calling it from resume is allowed. The refuse checks run before that call.

Do not add a new Rust file in this plan. Append tests to `flush_lifecycle/tests/initialize.rs`, which is already in `node-chainstate-adapter`. That file is 100 lines; keep it at or below 628. Do not edit `docs/parity/source-breadcrumbs.json` here (Plan 04 owns the next edit of that file).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Durable prune_intent → startup | The intent is untrusted until the hash matches the active chain and the height is outside locks and the keep window |
| Coins best-block vs chain tip | A tip that is not the recorded active tip means the delete batch is not a successful prune |
| Refuse → operator recovery | The error must not be read as automatic reindex |

| T-148-14 | Spoofing | missing mate | mitigate | Finish calls `commit_paired_delete`, which does not call `save_block` or `save_undo`. Task 2 asserts the absent mate is not replaced. |
