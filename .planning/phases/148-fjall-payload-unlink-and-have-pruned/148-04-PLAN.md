# Phase 148 Plan 04: Drop Deleted Hashes from the Block Cache

<objective>
Evict hashes that a durable prune deleted from `blocks_by_hash` before the flush closure returns, so inventory cannot treat cache presence as payload presence (D-14, D-15).

Purpose: `payload_present` is cache presence OR durable presence. A deleted key with the body still in the cache would resurrect the block.
Output: `prune_flush.rs` and a cache test. No `Pruned` label, no limited-service advertisement, no snapshot rewrite.
</objective>

`blocks_by_hash` is a private field on `ManagedPeerNetwork` (`network.rs`). `runtime_authority` is a child module, so `prune_flush.rs` may remove keys directly.

```rust
pub(super) fn flush_and_evict_pruned_blocks<S, V>(
    network: &mut ManagedPeerNetwork<S, V>,
    mode: FlushMode,
    now: FlushPolicyTime,
    disk_free_bytes: u64,
    plan: &PrunePlan,
    locks: &[PruneLockInfo],
) -> Result<FlushExecution, StorageError>
where
    S: FlushPersistSink,
    V: CoinsView,
{
    let execution = network.chainstate_mut().flush_applying_plan(
        mode, now, disk_free_bytes, plan, locks,
    )?;
    for hash in &execution.deleted_block_hashes {
        network.blocks_by_hash.remove(hash);
    }
    Ok(execution)
}
```

`ManagedNetworkHandle::flush_coins` calls that function with `PrunePlan::default()` and `&[]` inside the existing `mutate` closure, then maps `StorageError` to `ManagedNetworkAuthorityError::LifecycleEffect` as it does today.
