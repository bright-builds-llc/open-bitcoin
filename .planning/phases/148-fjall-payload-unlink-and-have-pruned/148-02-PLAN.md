Plan 01 exports `PairedDeleteOutcome` from `crate::storage::fjall_store` and `FjallNodeStore::commit_paired_delete(height, block_hash)`.

Add this classification in `flush_lifecycle/prune_apply.rs`. It calls `height_forbidden_by_any_lock` and `height_inside_keep_window`. It does not reimplement 288 or 10.

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum HeightPruneOutcome {
    DeletedLiveMate { height: u32, block_hash: BlockHash },
    AlreadyAbsent { height: u32, block_hash: BlockHash },
    SkippedLock { height: u32 },
    SkippedKeepWindow { height: u32 },
    SkippedUnresolved { height: u32 },
}

pub(crate) enum ClassifiedHeight {
    Ready { height: u32, block_hash: BlockHash },
    SkippedLock { height: u32 },
    SkippedKeepWindow { height: u32 },
    SkippedUnresolved { height: u32 },
}

pub(crate) fn classify_prune_height(
    height: u32,
    active_chain: &[ChainPosition],
    locks: &[PruneLockInfo],
) -> ClassifiedHeight;
```

Classification rules:
- No `active_chain.last()` → `SkippedUnresolved`. Tip height is that last position's `height`, not the slice index.
- `height_forbidden_by_any_lock(height, locks)` → `SkippedLock` (check locks before keep window so a protected keep-window height is `SkippedLock`).
- `height_inside_keep_window(tip, height)` → `SkippedKeepWindow`.
- Else find `active_chain.iter().find(|position| position.height == height)`. Missing → `SkippedUnresolved`. Do not consult header entries.
- Present → `Ready { height, block_hash: position.block_hash }`.

```rust
fn commit_paired_unlink(
```

`#[allow(clippy::too_many_arguments)]` matches the existing `execute_flush`. Do not add a second flusher.

Empty `plan.heights`: behavior of `execute_flush` stays the current function, including `FlushDecision::None` and `RefuseDiskSpace` before `persist_ordered_prefix` (D-06).

Non-empty plan:
- Not ready still returns the existing `coins_corruption("flush before ready")` and deletes nothing.
- Compute `decide_flush` as today.
- Call `persist_ordered_prefix`, then `apply_prune_plan`, then coins only when `coins_write_kind` is `Some`, then `persist_chain_meta` only when coins were written (D-11).
- `FlushDecision::None`: prefix + unlink, no coins, no chain meta, `Ok` with `wrote_coins: false`.
- `RefuseDiskSpace`: prefix + unlink, no coins, no chain meta, then the existing `Err(refuse_disk_space())`. Hashes already passed to `on_deleted` stay deleted.

`apply_prune_plan` loops plan heights in order. Skips append the skip outcome and continue (D-13). `Ready` calls `sink.commit_paired_unlink`. `DeletedLiveMate` pushes the hash onto `deleted_block_hashes` and calls `on_deleted` before the next height. `AlreadyAbsent` does not set a flag and does not count as a deleted hash. A sink `Err` returns that error after earlier `on_deleted` calls have already run.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PrunePlan heights → active chain | Heights are untrusted until they match one active-chain ChainPosition |
| Supplied locks and tip → deletion | A stale plan is re-checked at unlink time |
| Deleted hash → in-memory undo map | The next prefix must not see an undo the disk delete already removed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-148-07 | Tampering | `classify_prune_height` | mitigate | `height_forbidden_by_any_lock` skips the height. Task 2 keeps that height's block and undo keys. Skipping does not fail the rest of the plan. |
| T-148-08 | Denial of service | keep window | mitigate | `height_inside_keep_window` skips tip-window heights before `commit_paired_unlink`. Unlink does not widen 288. |
| T-148-09 | Repudiation | empty plan / prune config | mitigate | Empty `plan.heights` uses the existing early return and does not call `commit_paired_unlink`. Production paths do not read `PruneMode` or call `plan_automatic_prune`. |
| T-148-10 | Tampering | partial height | mitigate | Only `DeletedLiveMate` is appended to `deleted_block_hashes`. A sink error is returned after earlier committed hashes were forgotten, and is not reported as a fully successful plan. |
| T-148-11 | Tampering | coins best-block | mitigate | This plan does not put coins writes in the unlink loop. Task 2 asserts `best_block` is unchanged. Coins flush stays after unlink (D-11). |
| T-148-12 | Spoofing | undo resurrection | mitigate | `forget_undo` runs for every hash `on_deleted` saw, including when a later height errors. Task 2's second flush still sees `has_undo == false`. |
</threat_model>
