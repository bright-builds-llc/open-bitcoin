`ManagedChainstate::flush_applying_plan` pushes every `on_deleted` hash into a local `deleted` vec, then calls `forget_undo`, then returns `result`. `apply_prune_plan` calls `on_deleted` only for `HeightPruneOutcome::DeletedLiveMate`, and only after `commit_paired_unlink` returns `PairedDeleteOutcome::DeletedLiveMate`. That callback runs before `complete_coins_write` can return `Err(refuse_disk_space())`, `cache.flush` / `cache.sync` can fail, or `persist_chain_meta` can fail. It also runs for earlier heights when a later height's `commit_paired_unlink` returns `Err` and `apply_prune_plan` aborts with `?`. A prefix persist error or an empty-plan `RefuseDiskSpace` leaves `deleted` empty.

`PairedDeleteOutcome::AlreadyAbsent` is not pushed and does not call `on_deleted` (`prune_apply.rs`). Leave that. Do not add `AlreadyAbsent` hashes to `deleted_block_hashes`. The retry cannot evict; the failing call that committed the delete must have already evicted.

`ManagedNetworkHandle::mutate` returns `Ok(command(&mut network))`. It does not roll the network back when the closure's value is `Err`. Removal must happen inside `flush_and_evict_pruned_blocks` before that function returns `Err`. Do not remove keys in the outer `map_err` of `flush_applying_prune_plan` or `flush_coins`: that arm runs after `mutate` has dropped the lock.

Replace the `?` in `flush_and_evict_pruned_blocks` with:

```rust
let outcome = network.chainstate_mut().flush_applying_plan(
    mode, now, disk_free_bytes, plan, locks,
);
let deleted = match &outcome {
    Ok(execution) => execution.deleted_block_hashes.clone(),
    Err(failure) => failure.deleted_block_hashes.clone(),
};
for hash in &deleted {
    network.blocks_by_hash.remove(hash);
}
outcome.map_err(|failure| failure.error)
```
