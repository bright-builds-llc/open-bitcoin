```rust
// fjall_store/prune.rs
pub(crate) const HAVE_PRUNED_KEY: &str = "have_pruned";
pub(crate) const PRUNE_INTENT_KEY: &str = "prune_intent";

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum PairedDeleteOutcome {
    DeletedLiveMate,
    AlreadyAbsent,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) struct PruneIntent {
    pub height: u32,
    pub block_hash: BlockHash,
}

impl FjallNodeStore {
    pub(crate) fn load_have_pruned(&self) -> Result<bool, StorageError>;
    /// Ok(None) when the key is absent. 36-byte value decodes. Any other length is Corruption + Repair.
    pub(crate) fn maybe_prune_intent(&self) -> Result<Option<PruneIntent>, StorageError>;
    /// Sync-inserts prune_intent only. Does not insert have_pruned.
    pub(crate) fn sync_prune_intent(&self, intent: PruneIntent) -> Result<(), StorageError>;
    pub(crate) fn commit_paired_delete(
        &self,
        height: u32,
        block_hash: BlockHash,
    ) -> Result<PairedDeleteOutcome, StorageError>;
}

// coins.rs
pub(super) fn undo_key(block_hash: BlockHash) -> String;
impl FjallNodeStore {
    pub fn has_undo(&self, block_hash: BlockHash) -> Result<bool, StorageError>;
}
```

`fjall_store.rs` gains only `mod prune;` and `pub(crate) use prune::PairedDeleteOutcome;`. It is 624 lines and the file-length gate is 628. Do not move other helpers into that file.

Keys (D-02):
- Block payload: existing `block_key` in the `block_index` keyspace (`block:` + 64 lowercase hex).
- Undo: existing `undo_key` in the `chainstate` keyspace (`undo:` + the same hex).
- `have_pruned` and `prune_intent` live in the `block_index` keyspace.
- Intent value is little-endian `u32` height followed by the 32-byte hash (36 bytes).
- `have_pruned` value is the single byte `1u8`.

`PersistMode::Sync` is `FjallPersistMode::SyncAll` (`fjall_store.rs` `fjall_persist_mode`). Use `self.db.batch()`, then `durability(Some(FjallPersistMode::SyncAll)).commit()`. Do not call `remove_bytes` for a pair. Do not call `commit_batch` in `coins_view.rs`. Do not call `batch_write_capped`. Do not write `encode_best_block_key()` (`[b'B']` in the coins keyspace).

`commit_paired_delete` sequence for a height whose `has_block || has_undo` is true (D-01, D-05, D-07):
1. `sync_prune_intent`. That commit must not insert `HAVE_PRUNED_KEY`.
2. One second Sync batch that `remove`s the block key, `remove`s the undo key, `insert`s `HAVE_PRUNED_KEY`, and `remove`s `PRUNE_INTENT_KEY`.
3. Post-check `has_block` and `has_undo`. Both false returns `DeletedLiveMate`. Either true returns `StorageError` (not `Ok`).

Both mates already absent (D-03, D-06 at the store): return `AlreadyAbsent` without an intent write and without inserting `have_pruned`.

One mate already absent (D-03): run the same two-commit sequence. Do not call `save_block` or `save_undo`.

On `commit` `Err`: map to `StorageError::BackendFailure` and return. Do not retry the batch and do not write a follow-up `have_pruned` commit. Fjall poisons the database after a failed persist.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller hash → Fjall tombstones | A hash is deleted only when passed to `commit_paired_delete`; this plan does not scan namespaces for heights |
| Delete batch → durable flag | `have_pruned` becomes durable only as an item in the same Sync batch as the two tombstones |
| Delete batch → coins keyspace | Coins best-block and head-blocks bytes must not cross into this batch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-148-01 | Tampering | `commit_paired_delete` | mitigate | One `db.batch()` removes both mate keys. Post-check returns `StorageError` if either `contains_key` is still true. `remove_bytes` is forbidden in `prune.rs` (task 1 acceptance). |
| T-148-02 | Repudiation | `HAVE_PRUNED_KEY` | mitigate | Insert the key only in the second Sync batch, and only after has_block or has_undo is true. Both-absent returns `AlreadyAbsent` with no insert. `RuntimeMetadata` is not a flag home. |
| T-148-03 | Denial of service | coins best-block key | mitigate | Batch touches `block_index` and `chainstate` mate/intent keys only. Task 1 asserts `encode_best_block_key` bytes are unchanged. |
| T-148-04 | Tampering | height selection | mitigate | This plan has no height scan. Acceptance forbids `prefix(` over `block:` or `undo:` in `prune.rs`. Plan 02 re-checks locks before calling `commit_paired_delete`. |
| T-148-05 | Spoofing | payload bytes | mitigate | `commit_paired_delete` must not call `save_block` or `save_undo`. A missing mate stays missing. |
| T-148-06 | Elevation of privilege | recovery action | mitigate | Truncated intent decode returns `StorageError::Corruption` with `StorageRecoveryAction::Repair`. Do not return `Reindex` or call `mark_interrupted_write`. |
