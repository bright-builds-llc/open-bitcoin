<threat-model>
## Assets

- Live mempool membership/index/resource/rolling coherence and committed lifecycle facts.
- Existing single-admission compatibility.
- Prepared-transition integrity between evaluation and apply.

## Trust Boundaries

| Boundary | Untrusted or mutable state crossing it |
| --- | --- |
| Transaction + chainstate → candidate preparer | Arbitrary candidate and contextual inputs |
| Immutable mempool view → prepared transition | Snapshot-dependent conflicts, fees, limits, and rolling floor |
| Prepared transition → live `Mempool` | Potentially stale base revision |

## Threats and Mitigations

| Threat ID | STRIDE | Threat | Disposition | Concrete mitigation |
| --- | --- | --- | --- | --- |
| T-132-06 | Tampering | Stale-base transition overwrites newer membership or rolling state | mitigate | Task 2 compares complete monotonic revision before any assignment |
| T-132-07 | Tampering | Apply fails after partial field assignment or overwrites untouched live state | mitigate | Task 2 revision-checks first, moves all fallible work into preparation, and applies only the owned sparse patch |
| T-132-08 | Denial of Service | Candidate preparation clones/recomputes live mempool | mitigate | Task 1 provides a read-only preparer and grep/test ban on entry clones |
| T-132-09 | Elevation of Privilege/Policy bypass | A mutation path changes rolling or membership without revisioning | mitigate | Task 2 inventories admission, pressure, expiry, block, reorg, and rolling mutation owners with path-specific tests |
| T-132-10 | Information Disclosure/Effect leakage | Pure candidate engine publishes relay/persistence/evidence effects | mitigate | Task 1 limits output to typed candidate facts and contains no adapter dependency |

## Security Verification

- Stale tests independently mutate membership and rolling-only state, then assert full before/after equality on failed apply.
- Full mempool library regression suite plus objective stage probes prove legacy single admission behavior and failure order.
- Source scans prove the candidate module has no live field assignments or adapter imports.
- Source scans prove no `PreparedMempoolTransition` exists, `MempoolPatch` has no full `MempoolState`, and normal apply has no recomputation/materialization.
