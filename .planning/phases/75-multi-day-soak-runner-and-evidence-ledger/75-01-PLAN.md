<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/domain -> datadir files | Parsed operator input becomes durable run index and JSONL ledger files under the selected datadir. |
| Ledger -> report projections | Durable ledger events become shareable JSON and Markdown reports. |
| Shared sync/support evidence -> soak outcome | Existing status/support contracts are wrapped into soak-owned final labels. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-75-01-01 | Tampering | `operator/soak/ledger.rs` | mitigate | Use schema-versioned envelopes, increasing sequence numbers, full JSON lines, size caps, `sync_all`, partial-line detection, and atomic `run-index.json.tmp` rename. |
| T-75-01-02 | Repudiation | `operator/soak/report.rs` | mitigate | Reports must contain `is_projection: true`, `source_ledger_path`, and `latest_sequence` so stale moved reports are not mistaken for current durable state. |
| T-75-01-03 | Information Disclosure | `operator/soak/report.rs` | mitigate | Report projection must allowlist compact status fields and reject raw daemon logs, raw live-smoke reports, wallet material, RPC credentials, and unbounded peer tables. |
| T-75-01-04 | Denial of Service | `operator/soak/ledger.rs` | mitigate | Enforce `MAX_SOAK_EVENT_BYTES = 16 * 1024` and `MAX_SOAK_RUNS_IN_INDEX = 32`; tests must cover both bounds. |
| T-75-01-05 | Spoofing | `operator/soak/outcome.rs` | mitigate | Do not infer success from headers or downloads; classify clean completion only from shared stop/status/support evidence fields. |
</threat_model>
