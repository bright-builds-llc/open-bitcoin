<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| peer getdata -> managed serving | Untrusted inventory requests reach runtime transaction lookup and must be classified before data is served. |
| mempool admission -> fanout queues | Accepted runtime transactions become outbound inventory announcements only after eligibility and suppression checks. |
| lifecycle cleanup -> relay state | Chainstate/mempool removals must revoke serving and fanout eligibility immediately. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-104-02-01 | Information Disclosure | `serve_inventory` | mitigate | Serve `tx` only for `TxServeOutcomeLabel::Served`; emit `notfound` for stale, confirmed, rejected, replaced, evicted, expired, identity mismatch, unknown, and not relay eligible outcomes. |
| T-104-02-02 | Elevation of Privilege | `ManagedRelayFanoutState` | mitigate | Build fanout peer input through `classify_relay_eligibility` using `RelayActivationConfig`, inbound serving state, connection class, and relay permission effects. |
| T-104-02-03 | Denial of Service | fanout queues | mitigate | Use Plan 01 queue cap, drain cap, and fake-clock interval; add managed tests for cap and deterministic draining. |
| T-104-02-04 | Tampering | txid/wtxid translation | mitigate | Use `TxRelayPeerMode::from_remote_wtxidrelay` and `TxRelayId::to_inventory_vector`; do not construct transaction inventory from raw hashes without peer mode. |
| T-104-02-05 | Repudiation | relay evidence info | mitigate | Record fixed labels and counts for served, notfound, suppressed, queued, cleaned, and rebroadcast-deferred outcomes so tests can prove behavior without raw identifiers. |
</threat_model>
