## Summary

Implement BASIC selection/hash/commitment logic in existing pure crates, with a narrow chainstate projection that proves input completeness before invoking the generator. Existing SHA256d and CompactSize can be reused; SipHash currently exposes only a fixed 32-byte Wtxid path and needs arbitrary-byte SipHash-2-4. The chainstate already records spent coins in transaction/input order, including coins created earlier in the same block. [VERIFIED: consensus/src/crypto.rs; crypto/siphash.rs; codec/src/compact_size.rs; chainstate/src/engine/apply.rs]

The pinned corpus has ten testnet block cases covering genesis, empty data, empty outputs/spends, duplicate pushdata, OP_RETURN, malformed script and witness data. It tests exact bytes and headers, but flattens historical scripts into one synthetic CTxUndo; that layout must not weaken the production per-transaction undo boundary. Add edge-case oracle vectors and an actual validated continuous chain, with distinct scripts so deduplication cannot conceal missing spent history. [VERIFIED: Knots src/test/data/blockfilters.json; src/test/blockfilter_tests.cpp; phase154 context]

**Primary recommendation:** Extend primitives/codec/consensus, add `chainstate::block_filter` projection from staged validated undo, and prove exact bytes independently before introducing index effects. [VERIFIED: CONTEXT D-01/D-06/D-07; inspected dependency graph; recommended design]

### Pattern 1: Complete historical input projection

Require block hash/header correspondence to the validated `ChainPosition`. For height zero, require the validated null-parent genesis identity and zero spent scripts. For every non-genesis block require explicit undo, even when it is a complete empty coinbase-only undo. Verify `undo.transactions.len() == block.transactions.len() - 1`, then each undo input count against the matching non-coinbase transaction. Borrow scripts from `Coin.output.script_pubkey`, preserving transaction/input order at the boundary. Wrong identity/height/shape is a typed error, not an empty filter. [VERIFIED: CONTEXT D-01/D-02; chainstate types.rs; engine/apply.rs; recommended design]

The strongest available provenance seam is `StagedChainstateConnect`: staging calls `apply_connect_on_overlay`, which validates and constructs undo; `absorb_staged_connect` then installs that undo by block hash. `PreparedChainstateConnect` holds the stage privately and is the later runtime forwarding seam. A stand-alone `BlockUndo` shape check proves completeness/layout, not the truth of arbitrary manually supplied script bytes; actual validation or retained-authority provenance supplies that stronger guarantee. [VERIFIED: chainstate engine.rs/stage.rs; node chainstate.rs]

### Pattern 2: Exact BASIC algorithm

1. Include all nonempty outputs except scripts whose **first byte** is `0x6a`; include all nonempty historical spent scripts, with no OP_RETURN exclusion on the spent side. Do not parse scripts or exclude them using general UTXO unspendability helpers. [VERIFIED: pinned BuildFilterElements]
1. Deduplicate raw byte strings before computing N; preserve equal mapped values from distinct scripts. [VERIFIED: ElementSet/BuildHashedSet]
1. SipHash-2-4 keys are little-endian u64 words from raw block-hash bytes `[0..8]`/`[8..16]`; hash arbitrary-length scripts with full tail handling. [VERIFIED: BuildParams; crypto/siphash.cpp]
1. `F=N*784931`, `mapped=((hash as u128)*(F as u128)>>64) as u64`; P=19. Sort mapped values and encode deltas from zero. Quotient is q one-bits then zero; remainder is 19 bits most-significant first; final padding is zero. Prefix canonical CompactSize N. Empty filter is `[0x00]`. [VERIFIED: blockfilter.cpp/.h; util/golombrice.h; streams.h]
1. Filter hash is SHA256d(encoded bytes). Header is SHA256d(raw filter hash || raw previous header), 64 bytes total. [VERIFIED: blockfilter.cpp GetHash/ComputeHeader; BIP157]

### Pattern 3: Explicit ancestry without index work

Use an explicit genesis/previous commitment input, with previous block hash, height and typed filter header for non-genesis. Validate it against the block's parent/position; do not let `None` or arbitrary zero silently initialize a suffix. Header hashing itself can remain a reusable primitive that accepts a typed predecessor. Replacement branches reuse their common-ancestor header and then their own ordered descendants; do not carry over a displaced tip header. [VERIFIED: D-04/D-05; pinned ComputeHeader; proposed boundary]

## Common Pitfalls

### Output/spent exclusion asymmetry

Blanket OP_RETURN filtering drops undo scripts that Knots retains. Also, `engine/apply.rs::is_unspendable_script` includes oversized-script rules that BASIC's output selector does not use. Apply the precise filter selector, independent of coins eligibility. [VERIFIED: blockfilter.cpp; engine/apply.rs]

### Same-block spend concealed by duplicates

Undo captures same-block spends because each transaction's outputs enter the overlay before the next transaction is validated/spent. A same-block-created script is also an output script, so bytes alone cannot prove that the undo projection includes it. Assert the historical projection/undo contents directly with distinct scripts, then assert the final pinned bytes. [VERIFIED: apply_connect_transactions; BuildFilterElements; derived verification recommendation]

### Flattened oracle undo mistaken for production shape

Knots JSON test accumulates every fixture prevout into one synthetic CTxUndo. Use the lower script-input generator for the corpus, or regroup according to decoded transactions/input counts. Do not special-case the strict production constructor to accept that synthetic flat shape. [VERIFIED: blockfilter_tests.cpp blockfilters_json_test]

### Wrong count, collision or endian semantics

Avoid modulo mapping, deduplication after mapping, displayed/reversed block-hash keys, little-endian Rice bits, and missing zero-padding. Test raw duplicate scripts separately from mapped collisions; N counts distinct raw scripts even when two map to the same value. [VERIFIED: pinned blockfilter.cpp; streams.h; golombrice.h]

### Successful staging confused with successful durable commit

The node's `commit_prepared_connect` absorbs state before `persist()`, and persistence can fail after accepted in-memory state changes. This phase exposes pure facts only; later lifecycle planners must not assume success-only callback indexing covers this boundary. [VERIFIED: node/src/chainstate.rs commit_prepared_connect]
