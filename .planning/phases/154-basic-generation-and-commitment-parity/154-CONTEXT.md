## Implementation Decisions

### Script-history authority

- **D-01:** Use validated historical spent-output facts/undo, including same-block-created-and-spent outputs. Do not reconstruct spent scripts from the current coins view.
- **D-02:** Treat missing or mismatched non-genesis spent-script evidence as an explicit error. Genesis alone may use the proven no-undo path; a complete coinbase-only non-genesis block may have an explicit empty spent set.
- **D-03:** Match the pinned BASIC rules for empty scripts, output OP_RETURN exclusion and raw-script de-duplication before range mapping; preserve mapped collisions.

### Commitment identity

- **D-04:** Use typed filter hash/header identities with explicit raw bytes versus display hex. Derive SipHash keys from the raw block hash and use a zero predecessor only at genesis.
- **D-05:** Make predecessor/branch identity explicit so replacement ancestry changes the header correctly without introducing an index lifecycle in this phase.

### Parity and scope

- **D-06:** Use independent pinned Knots vectors and an auditable oracle for extra edge cases; expected bytes must not be generated by the Rust implementation under test.
- **D-07:** Extend existing crates without production dependencies. Keep codec/hash/domain layers pure and historical-input adapters narrow.
- **D-08:** No GUI work is required: the roadmap UI hint comes from protocol header terminology. Preserve BASIC-only and all existing no-production-claim boundaries.

### Agent Discretion

Module names, exact fallible boundary types, and fixture organization may follow research findings. Add only the necessary validated-input projection for later index callers.
