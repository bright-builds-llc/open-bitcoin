<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| caller to mempool core | Untrusted peer or local transaction data enters pure admission logic as `Transaction`. |
| mempool core to later observability | Outcome values may carry txid/wtxid internally for downstream relay/RPC consumers, but only fixed labels are safe for shared evidence. |
| managed node to mempool core | Adapter code calls admission but must not reinterpret errors by strings. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-102-01-01 | Tampering | `Mempool::accept_transaction_outcome` | mitigate | Preserve prospective-state admission and add snapshot tests for entries, spent-outpoint indexes, virtual-size totals, parents, children, and replacement state. |
| T-102-01-02 | Information Disclosure | `MempoolOutcome` label APIs | mitigate | Keep `label().as_str()` and rejection category labels fixed; do not add raw transaction hex, txids, wtxids, peer endpoints, permissions, credentials, or dynamic labels to evidence strings. |
| T-102-01-03 | Denial of Service | missing-parent mapping | mitigate | Return deterministic unique parent txids and leave storage/orphan staging to bounded Plan 02/03 logic; do not allocate unbounded evidence strings. |
| T-102-01-04 | Tampering | managed mempool wrapper | mitigate | Add `submit_transaction_outcome` instead of asking callers to pattern-match `MempoolError` display text. |
| T-102-01-05 | Elevation of Privilege | peer/socket mutation of mempool state | accept | This plan exposes pure/managed mempool methods only and does not modify peer/socket code; Plan 03 mitigates the runtime bridge. |
</threat_model>
