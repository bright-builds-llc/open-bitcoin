# Phase 72 - UI Design Contract

> Visual and interaction contract for operator terminal, CLI status, RPC/status evidence, metrics/log projections, live-smoke summaries, and support bundles. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none; Rust CLI, Ratatui terminal dashboard, JSON, Markdown, metrics, and structured logs | Detected no `components.json`, Tailwind, PostCSS, or `package.json`; RESEARCH Standard Stack |
| Preset | not applicable | Rust terminal/status phase, not React/Next.js/Vite |
| Component library | Ratatui 0.30.0 and Crossterm 0.29.0 for terminal dashboard; line-oriented CLI and Markdown renderers elsewhere | RESEARCH Standard Stack; `packages/open-bitcoin-cli/src/operator/dashboard/app.rs` |
| Icon library | none; use keyboard action letters and text labels, not icons | Existing dashboard action model |
| Font | terminal default monospace; support Markdown assumes monospace for code, commands, labels, and JSON field names | Existing CLI/TUI surfaces |

Design contract defaults:

- `OpenBitcoinStatusSnapshot` and nested `SyncStatus` are the only full-sync truth contract. Renderers may summarize, but must not reclassify sync state locally.
- Human-facing unavailable data renders exactly as `Unavailable: {reason}`.
- CLI, dashboard, RPC Open Bitcoin sync status, metrics/log projections, live-smoke summaries, and support bundles must agree on connected progress, best-known tip freshness, recovery category, peer health, and next action, or preserve the same unavailable reason.
- This phase must not introduce a hosted dashboard, browser UI, GUI, landing page, shadcn registry, web design system, or broad production-node claim.

## Terminal Surface Contract

| Surface | Contract | Source |
|---------|----------|--------|
| CLI human status | Keep stable `Label: value` lines. Add or preserve explicit lines for validated active-chain height/hash/work, best-known tip, stay-current state/action, latest reorg, reconcile progress, no-progress diagnosis/action, resource pressure, recovery category/action, peer detail, logs, metrics, and health. | CONTEXT D-01 through D-05 |
| CLI JSON status | Pretty-print the canonical `OpenBitcoinStatusSnapshot`; do not add a renderer-only status DTO. | CONTEXT D-01; existing `render_status` JSON path |
| Dashboard | Keep the existing 3-column Ratatui layout, bordered panels, title band, chart band, and action band. Add missing rows to the existing sections before adding a new section. | Existing dashboard app/model |
| Dashboard actions | Keep single-letter actions. `r` refresh, `s` status, `q`/Esc/Ctrl-C quit. Service-affecting actions require explicit `y` confirmation or `n` cancellation. | Existing dashboard action model |
| RPC Open Bitcoin sync status | Expose the same durable sync evidence when available. Do not widen baseline-compatible `getblockchaininfo` for support-only fields. | CONTEXT D-06 |
| Metrics and logs | Keep metrics bounded numeric samples and logs compact structured records. Use shared labels for progress, stop reason, recovery, no-progress, reorg, peer contribution, and resource pressure. | CONTEXT D-07; `docs/architecture/operator-observability.md` |
| Live-smoke summary | In support evidence, include allowlisted summary fields only. Do not embed raw live-smoke reports, daemon stdout/stderr, raw logs, endpoint tables, cookies, passwords, or wallet material. | CONTEXT D-09, D-12 |
| Support bundle Markdown | Render a compact human index with redaction, config, full-sync evidence, status snapshot, store health, live-smoke summary, and final verdict sections. | CONTEXT D-09 through D-11 |

Required full-sync evidence fields:

- Initial and final best-known tip height/hash/work/freshness/source.
- Connected active-chain height/hash/work and validated active-chain height/hash/work.
- Header height and downloaded block height, explicitly separate from connected/validated progress.
- Restart/resume checkpoints, same-datadir evidence, clean/unclean prior shutdown, stale in-flight verdict, and recovery category/action.
- Stay-current window, stay-current state, and stay-current next action.
- Peer contribution summary and bounded peer health.
- No-progress diagnosis/action, latest reorg, reconcile progress, resource pressure, and final evidence-derived verdict.

Verdict labels:

- `sync_to_tip_proven`
- `stay_current_proven`
- `diagnosed_blocker`
- `inconclusive`

Verdicts must cite the fields that justify them. Bundle existence, elapsed time, peer reachability, and daemon startup are never sufficient proof by themselves.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage | Source |
|-------|-------|-------|--------|
| xs | 4px | Inline gap between keyboard key and action label; one literal terminal space | Default adapted to terminal cells |
| sm | 8px | Action separators (` | `), compact row grouping, list item rhythm | Existing dashboard action line |
| md | 16px | Default section separation in support Markdown; one blank line around `##` sections | Default adapted to Markdown |
| lg | 24px | Major evidence groups: status snapshot, full-sync evidence, live-smoke, verdict | Phase 72 support evidence scope |
| xl | 32px | Top-level support-bundle group breaks and docs examples | Default |
| 2xl | 48px | Reserved for long-form operator docs, not dashboard rows | Default |
| 3xl | 64px | Reserved; do not use inside compact terminal dashboard/status surfaces | Default |

Exceptions: No pixel-layout exceptions. Terminal renderers map the scale to cells, rows, borders, and blank lines. Preserve existing Ratatui fixed bands: title band 3 rows, chart band 8 rows, action band 4 rows, and the existing minimum interactive dashboard height blocker.

## Typography

| Role | Size | Weight | Line Height | Usage | Source |
|------|------|--------|-------------|-------|--------|
| Body | 14px | 400 | 1.5 | CLI values, dashboard values, support Markdown body | Default adapted to terminal monospace |
| Label | 14px | 400 | 1.5 | `Label: value` prefixes, dashboard row labels, evidence field names | Existing CLI/dashboard rows |
| Heading | 16px | 600 | 1.2 | Dashboard section headings, support Markdown `##` sections | Existing Ratatui bold section titles |
| Display | 20px | 600 | 1.2 | `Open Bitcoin Dashboard` title and support Markdown H1 only | Existing dashboard title |

Rules:

- Use only weights 400 and 600. In Ratatui, weight 600 maps to `Modifier::BOLD`.
- Do not scale font size with terminal size or viewport width.
- Keep row labels short enough to fit in compact terminal columns. Prefer stable machine labels over prose.
- Use snake_case for machine verdicts and labels, not title-case prose, when the value is a status enum.

## Color

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) | Terminal default background and foreground; reference `#0B0F14` background / `#E5E7EB` foreground only for docs | Main terminal/status surface; do not force background color | Existing terminal defaults |
| Secondary (30%) | Ratatui `Color::Gray` / `Color::DarkGray`; reference `#9CA3AF` / `#4B5563` | Labels, separators, borders, secondary metadata | Existing dashboard labels/separators |
| Accent (10%) | Ratatui `Color::Cyan` (`#00FFFF`) and data-only `Color::Green` (`#00FF00`) | Cyan for dashboard title and section headings; green for metric sparkline glyphs only | Existing dashboard app |
| Destructive | Ratatui `Color::Yellow` (`#FFFF00`) | Service-affecting action keys, destructive confirmation prompt, and window/action blockers only | Existing dashboard app/action |

Accent reserved for: dashboard title, dashboard section headings, support-bundle verdict heading, and metric sparkline glyphs. Do not use accent for every interactive element.

Color must not be the only carrier of meaning. Destructive service actions must remain text-labeled and confirmation-gated even when color is disabled.

## Copywriting Contract

| Element | Copy | Source |
|---------|------|--------|
| Primary CTA | Generate support bundle | OBS-02; support bundle command |
| Empty state heading | No support evidence available | Default |
| Empty state body | Run `support bundle --output-dir=<path>` after collecting status evidence. Attach a live-smoke report only when intentionally summarizing opt-in UAT evidence. | AGENTS UAT lesson; CONTEXT D-12, D-15 |
| Error state | Support evidence unavailable: {reason}. Inspect the selected datadir, run status JSON, and rerun support bundle with an explicit output directory. | Default from support command failure paths |
| Destructive confirmation | Service action: `Confirm apply: {effect}. Press y to confirm or n to cancel.` | Existing `action_confirm_text` |
| Unavailable field | `Unavailable: {reason}` | CONTEXT D-04; architecture docs |
| Sync-to-tip verdict | `Evidence verdict: sync_to_tip_proven` followed by the active-chain height/hash/work and best-known tip fields that prove it. | CONTEXT D-11 |
| Stay-current verdict | `Evidence verdict: stay_current_proven` followed by best-known tip freshness, stay-current state, and matching active-chain evidence. | CONTEXT D-11 |
| Blocker verdict | `Evidence verdict: diagnosed_blocker` followed by recovery category/action, no-progress diagnosis/action, storage/resource pressure, or reorg evidence. | CONTEXT D-11 |
| Inconclusive verdict | `Evidence verdict: inconclusive` followed by the missing evidence or unavailable reasons. | CONTEXT D-11 |

Destructive actions in this phase:

- `start service`
- `stop service`
- `restart service`
- `install service`
- `uninstall service`
- `enable service`
- `disable service`

Each destructive dashboard action must use the existing pending-action flow. Pressing `n`, any non-confirm action, or cancelling must not call the service manager.

Forbidden copy:

- Do not claim production-node readiness, inbound serving, relay, production-wallet safety, migration apply mode, signed packaging, GUI, hosted dashboard, or drop-in readiness.
- Do not say downloaded-only progress proves sync-to-tip.
- Do not describe public-mainnet live smoke as part of `bash scripts/verify.sh`.

## Evidence Alignment Requirements

| Requirement | Contract | Source |
|-------------|----------|--------|
| OBS-01 | All surfaces consume or summarize `OpenBitcoinStatusSnapshot`/`SyncStatus`; renderer-local sync classification is forbidden. | CONTEXT D-01 |
| OBS-02 | Support evidence includes redacted full-sync evidence, live-smoke summary only, resource pressure, restart/resume evidence, peer contribution, no-progress/reorg events, and typed verdict. | CONTEXT D-09 through D-12 |
| OBS-03 | Add deterministic cross-surface comparison fixtures/checker for CLI human, dashboard projection, RPC durable status, metrics/log projection, live-smoke summary, and support evidence. | CONTEXT D-08 |
| OBS-04 | Operator guidance explains exactly what the evidence proves and preserves deferred production scope boundaries. | CONTEXT D-13 |

Comparison rule: if surfaces disagree, the shared status snapshot wins and the renderer/projection should be fixed. A missing field is acceptable only when every surface preserves the same `Unavailable: {reason}`.
