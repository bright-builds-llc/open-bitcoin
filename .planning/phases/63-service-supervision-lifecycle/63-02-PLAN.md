<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/dashboard action -> service manager | Operator-selected effectful actions cross into launchd/systemd manager operations. |
| service manager adapter -> subprocess | Adapter code invokes local `launchctl` or `systemctl` without shell interpolation. |
| dashboard key input -> service action | Interactive keys can trigger pending service operations after confirmation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-63-02-01 | Elevation of Privilege | launchd/systemd adapters | mitigate | Use only user-scope commands: `launchctl ... gui/<uid>/org.open-bitcoin.node` and `systemctl --user ... open-bitcoin-node.service`; reject sudo and machine-wide paths through acceptance checks. |
| T-63-02-02 | Tampering | service start/stop/restart | mitigate | Check the Open Bitcoin user service file exists before effectful platform calls so actions do not target Core/Knots services or arbitrary manager entries. |
| T-63-02-03 | Repudiation | command outcomes | mitigate | Return `ServiceCommandOutcome` with exact command strings for every start, stop, and restart action. |
| T-63-02-04 | Denial of Service | dashboard service actions | mitigate | Require confirmation for start, stop, and restart; cancelled or pending actions must not call the manager. |
| T-63-02-05 | Tampering | subprocess invocation | mitigate | Use `Command::new(...).args([...])` only; no shell command strings, no path interpolation through a shell, and deterministic tests for rendered command strings. |
</threat_model>
