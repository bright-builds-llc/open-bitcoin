# Phase 97 - UI Design Contract

> Visual and interaction contract for the existing Open Bitcoin terminal/operator dashboard evidence path. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope Contract

Phase 97 is not a new frontend build. It must preserve the existing CLI/TUI dashboard visual and interaction contract while proving retained inbound metric samples render through the existing metrics history path.

Required evidence path:

`InboundPeerServingStatus` aggregate counters -> fixed low-cardinality `MetricSample` values -> existing `FjallNodeStore::append_metric_samples` retention -> existing dashboard metric history rendering.

Scope guard:

- Do not add a new dashboard screen, panel, modal, tab, chart component, color palette, keybinding, or operator workflow for Phase 97.
- Do not add peer identifiers, endpoints, raw permission class strings, ban scopes, reasons, runtime-created labels, addresses, or other dynamic dimensions to dashboard metric history.
- Do not change the public-network-free verification boundary.
- Do not use dashboard copy to claim transaction relay, compact block relay, mempool propagation, public inbound defaults, packaged service operation, or production full-node readiness.

Sources: Phase 97 context decisions D-01 through D-13, Roadmap Phase 97 success criteria, Requirements `INB-05` and `DOS-04`, and milestone audit gap `INT-02`.

## Dashboard Metrics Contract

Existing metric label coverage is the visual source of truth for inbound series. Phase 97 may prove retained samples for the registered inbound `MetricKind` values, but it must use the existing `metric_label` path instead of adding a second label registry.

Inbound metric label groups:

- Admission: `Inbound admits`, `Inbound rejects`, `Inbound cap rejects`, `Inbound reserved rejects`, `Inbound duplicate rejects`, `Inbound self-connection rejects`.
- Permission: `Inbound permissioned admits`, `Inbound protected admits`, `Inbound inactive permission effects`, `Inbound permission validation failures`.
- Peer policy: `Inbound eviction candidates`, `Inbound disconnects`, `Inbound active bans`, `Inbound misbehavior observations`, `Inbound protected no-actions`.
- Resource governance: `Inbound resource pressure`, `Inbound read queue pressure`, `Inbound write queue pressure`, `Inbound request cap reached`, `Inbound payload rejects`, `Inbound timeout disconnects`, `Inbound churn rejects`, `Inbound reconnect suppressions`.

Rendering contract:

- Retained inbound samples must remain `kind + numeric value + timestamp`.
- Non-finite or negative sample values render through existing sparkline clamping behavior as `0`.
- Width remains bounded by `retention.max_samples_per_series.min(60)`.
- Availability remains `available`, `Unavailable: no metric samples recorded`, or `Unavailable: {reason}`.
- The dashboard must not render raw inbound event details in chart labels or sparkline titles.

## Interaction Contract

Allowed interactions:

- `r`: refresh dashboard state from the shared snapshot.
- `s`: inspect service status through the shared service command path.
- `q`, `Esc`, or `Ctrl-C`: exit.
- Service-affecting actions retain the existing confirmation gate with `y` to confirm and `n` to cancel.

Disallowed interactions for Phase 97:

- No inbound-metrics filter selector.
- No metric-series picker.
- No peer drilldown.
- No endpoint drilldown.
- No export action.
- No dashboard settings action.
- No new destructive action.
