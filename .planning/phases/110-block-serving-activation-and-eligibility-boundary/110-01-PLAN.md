<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| config/CLI -> RuntimeConfig | Operator-controlled JSONC and CLI values are parsed into activation policy. |
| peer permissions -> eligibility policy | Permission-derived peer facts become block-serving eligibility inputs. |
| policy -> later runtime adapters | Pure decisions will gate future storage reads and socket responses. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-110-01-01 | Elevation of Privilege | `BlockRelayActivationPolicy` | mitigate | Default both `BlockServingActivationConfig.enabled` and `CompactRelayActivationConfig.enabled` to false; add tests proving transaction relay activation and permission effects cannot enable them. |
| T-110-01-02 | Spoofing | service-bit/public-serving evidence | mitigate | Keep `advertises_public_service` false and add `LocalPeerConfig::default().services` invariance tests so activation does not imply a public network service claim. |
| T-110-01-03 | Tampering | permission parsing integration | mitigate | Consume only typed `PermissionEffectLabel::DownloadServingPolicyInput` and `PeerConnectionClass`; reject raw permission strings after boundary parsing. |
| T-110-01-04 | Information Disclosure | eligibility labels | mitigate | Emit only fixed machine labels from `BlockServingEligibilityReason::as_str()`; do not include peer ids, endpoints, permission strings, credentials, block hashes, or dynamic text. |
| T-110-01-05 | Denial of Service | activation config parsing | accept | This plan adds only small fixed config fields and unit tests; resource request caps are handled in Plan 110-03. |
</threat_model>
