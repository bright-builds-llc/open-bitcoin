## Trust Boundaries

| Boundary | Description | Data crossing |
| --- | --- | --- |
| Raw candidate → selected identity | Exact root recognition cannot trust a null parent, shared body, claimed work or another network's genesis. | Untrusted header fields, complete transaction/body data |
| Identity/fixture carrier → ordinary authority | Immutable selected facts and owner scope require missing validation prerequisites; fixture success cannot supply them. | Selectors, supplied owners, imports, work/history carriers |
| Operator path → filesystem observation → backend | Shape inspection supplies unavailable identity/work facts and always refuses before backend recovery or writes. | Paths, symlinks, metadata, first directory entry |
| Daemon/RPC fallback → authority/effects | Refusal cannot become transient accepted authority, wallet/mempool recovery or a metrics worker. | Config, supplied/raw handles, optional durable sources |
| CLI source/live failure → offline/export/enrichment | Offline compatibility precedes metadata, lookup, destination and ledger effects; authenticated live failure remains visible. | Source/destination paths, wallet names, RPC response categories |
| Original receipt/source → current claim | Frozen bytes and narrowly reversible attribution remain historical evidence; current executable contracts use raw current source. | Historical receipts, snapshots, manifests, checker inputs and public claims |
