# Milestone v1.7: Full-Sync Soak and Recovery Hardening

**Status:** SHIPPED 2026-06-20
**Phases:** 75-81
**Total Plans:** 37
**Requirements:** 24/24 complete
**Audit:** passed

## Overview

v1.7 turned the v1.6 explicit opt-in sync-to-tip claim into a more durable
long-run operator-review workflow. The milestone focused on multi-day soak
stability, disk and resource bounds, corruption and lock recovery, progress
guarantees, stall diagnosis, richer diagnostics, and redacted "what happened"
support bundles for failed or degraded long runs.

The milestone does not include inbound serving, address relay, block serving,
transaction relay, compact block relay, production-funds wallet claims,
migration apply mode, destructive repair, automatic support-bundle upload,
signed packaging, Windows service support, GUI work, hosted dashboards,
public-network checks in `bash scripts/verify.sh`, multi-day wall-clock tests
as default gates, or broad production-node claims.

Raw v1.7 phase execution artifacts remain in `.planning/phases/` for parity
and UAT traceability.

## Milestone Summary

**Key decisions:**

- Keep public-network multi-day soak as explicit opt-in UAT evidence while default `bash scripts/verify.sh` remains deterministic, public-network-free, service-manager-free, and free of multi-day wall-clock gates.
- Treat v1.7 as soak and recovery hardening for the existing outbound full-sync workflow, not as production-node readiness.
- Preserve raw Phase 75 through Phase 81 artifacts in `.planning/phases/` for parity and UAT traceability.
- Require milestone-audit traceability to name requirement IDs directly in verification artifacts, not only in summaries or implementation evidence.

**Issues resolved:**

- Multi-day soak evidence now has durable run identity, resumable reports, typed stop reasons, and deterministic replay coverage.
- Long-run resource pressure now has shared bounds, preflight/runtime enforcement, operator rendering, support projection, and deterministic checker coverage.
- Lock and corruption recovery now has typed, non-mutating diagnosis across status, support, dashboard, and soak evidence.
- Progress and stall evidence now prevents false progress and explains last useful work, peer contribution, no-progress thresholds, and stalled subsystem causes.
- Support bundles now include redacted forensics for timelines, checkpoint chains, resource pressure, recovery events, peer outcomes, and final verdicts.
- The RES/REC orphan gaps from the first v1.7 audit are closed by Phase 81.

**Issues deferred:**

- Public-network multi-day soak and real service-manager runs remain opt-in UAT, not default deterministic gates.
- Production-node readiness, inbound serving, relay, production-funds wallet use, migration apply mode, automatic destructive repair, automatic support-bundle upload, signed packaging, Windows service support, GUI parity, hosted dashboards, and public-network CI remain future milestone scope.

**Technical debt:**

- `docs/parity/index.json` top-level `.surfaces[]` omits `phase78-progress-guarantees-stall-diagnosis`; checklist, audit sections, release docs, and requirement evidence still cover the Phase 78 mapping.
